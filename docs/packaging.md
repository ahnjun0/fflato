# 웹스토어 패키징

스토어 업로드 zip 에는 확장 실행에 필요한 것만 넣는다.

1.0.0 으로 실제 배포된 패키지의 내용은 다음과 같다 (설치본에서 확인):

    debug.html  debug.js  icon48.png  icon128.png
    LICENSE     manifest.json  plato-api.js  popup.html  popup.js  README.md

2.0.0 에서는 여기에 `src/` 가 추가되고 `plato-api.js` 가 빠진다.

제외: docs/, tools/, package.json, .git/, *.zip

`tools/` 는 검증 하니스이고 `docs/` 는 개발 문서다. 실행에 쓰이지 않으므로
패키지에 들어갈 이유가 없다. `.git/` 이 들어가면 저장소 이력 전체가 배포된다.

## 배포본 확인 방법

스토어에서 설치한 뒤 프로필의 확장 폴더를 직접 열어보는 것이 가장 확실하다.
개발자 대시보드보다 정확하다 — 사용자가 실제로 받는 파일 그대로다.

    ~/Library/Application Support/Google/Chrome/<프로필>/Extensions/<확장ID>/<버전>_0/

확장 ID 는 chrome://extensions 의 "세부정보" 에서, 프로필 경로는 chrome://version
에서 확인한다. manifest 의 `key` 와 `update_url` 은 Chrome 이 자동으로 붙이는
것이므로 저장소 manifest 와 달라도 정상이다.

## 권한 원칙

권한은 꼭 필요한 것만, 경고 문구가 붙지 않는 것으로 최소한만 늘린다.
경고가 붙는 권한(호스트 추가, `notifications` 등)을 추가하면 기존 사용자에게
재동의를 묻고 그때까지 확장이 비활성화된다. 권한을 **빼는** 것은 언제나 안전하다.

- `permissions` 는 `["storage"]` 하나만.
- `host_permissions` 는 `plato.pusan.ac.kr` 하나만.
- 로컬 저장은 **`chrome.storage.local`** 을 쓴다 (`"storage"` 권한 필요).
  `storage` 는 Chrome 이 경고 문구를 표시하지 않는 권한이라, 추가해도 기존
  사용자에게 재동의를 묻거나 확장을 비활성화하지 않는다. `localStorage` 는
  사용자가 인터넷 사용 기록을 지울 때 함께 지워질 수 있어 쓰지 않는다.
- **`chrome.storage.sync` 는 쓰지 않는다.** 같은 권한으로 쓸 수 있지만,
  출석 기록이 Google / Microsoft 의 동기화 서버로 올라간다. "어떠한 데이터도
  수집하지 않습니다" 라는 스토어 설명과 결이 어긋나고, 기기 간 공유로 얻는
  이득도 없다 (캐시가 없어도 서버 현황으로 복구된다).
- 호스트를 늘리지 않는다. 개편 전 시스템과의 대조는 마이그레이션 중에만
  필요했고 코드에 남기지 않았다 — 권한이 없으면 활성화될 수 없는 코드다.

## 동작 원칙

**최소 조건, 최소 기능.** 학교 서버를 쓰는 도구다. 안 해도 되는 요청은 하지 않고,
없어도 되는 기능은 만들지 않는다.

1. **사용자가 아이콘을 누를 때만** 네트워크 요청을 한다.
   백그라운드 폴링·주기 실행은 넣지 않는다.
2. **볼 순서를 정한다. 볼 대상을 줄이지는 않는다.** 감지용 페이지
   (`ubsmartbook/my.php`)는 194KB 다. 시간표를 캐시해 두고 지금 수업 중인
   과목부터 보되, 못 찾으면 결국 전부 본다.

   시간표를 **필터로 쓰면 안 된다.** 보강은 시간표에 없을 수 있다 — 다른
   요일에 하거나, 교수님이 보강을 원래 차시에 기록하면 표에 나타나지도
   않는다. "오늘 수업 없음" 을 "볼 필요 없음" 으로 해석하면 출결을 놓친다.

   **출석을 마친 과목도 계속 조회한다.** 한 차시에 자동출결이 여러 회차
   열릴 수 있고, 한 회차를 놓치면 등급이 내려간다(구 시스템 실측:
   1회차 미응답 + 2회차 응답 → 최종 지각). 조회에서 빼는 것은 출석부가
   아예 없는 강좌뿐이다.

   찾으면 거기서 멈추되, 보지 않은 과목이 있으면 그 사실을 화면에 알리고
   "전부 확인하기" 를 제공한다. 같은 시각에 다른 과목의 출결이 열려 있을
   수 있기 때문이다.
3. **동시 요청은 2개까지.** 실측상 전량 병렬 대비 87ms 밖에 차이나지 않는다.
   서버가 병목이라 버스트를 줄이는 것이 사실상 공짜다.
4. **쓰지 않는 것은 두드리지 않는다.** `action.php` 에는 smartHistory,
   hyflexHistory, details 등도 등록되어 있지만 프로파일에 넣지 않는다.
   `endpoints.js` 의 `actions` 목록이 곧 헬스체크의 요청 수다.
5. **sesskey 를 캐시한다.** 이걸 얻으려고 홈페이지(342KB, 실측 1067ms)를
   받는 것은 10글자를 위해 수업 중 경로의 68% 를 쓰는 셈이다. 캐시가 낡았는지
   미리 확인하지 않는다 — 확인 자체가 요청이다. 서버가 거부할 때만 갱신한다:

       웹서비스   → errorcode "invalidsesskey"
       action.php → HTTP 200 에 빈 본문

6. 헬스체크는 debug 페이지의 수동 버튼으로만 실행한다.
   팝업 진입이나 타이머에 걸지 않는다.

### 용량 표기

아래 수치는 **압축 전(HTML 원본)** 기준이다. 서버가 gzip 을 적용하므로
실제 전송량은 약 1/5 이다.

    ubsmartbook/my.php  압축 전 194KB → 실제 전송 44KB   (감지 · 일정 · 상태)
    홈페이지            압축 전 342KB → 실제 전송 64KB   (sesskey, 캐시됨)

파싱 비용과 서버 처리 부담은 압축 전 크기를 따르므로 두 수치를 함께 본다.

실측 (7과목, 학기 180개 수업 슬롯 시뮬레이션 · 압축 전 기준):

    세션이 열려 있을 때 — 이 확장을 실제로 쓰는 순간
      전과목 스캔   1,260요청  338MB
      순서 방식       240요청   64MB   (81% 감소)
      요청 수 분포: 1요청 120회 / 2요청 60회

    시간표에 없는 날의 보강 — 전부 발견, 놓침 0건 (평균 7요청)
    아무 세션도 없을 때 — 7요청. 기존과 동일하므로 회귀는 없다.

이득은 "찾았을 때 멈추는 것" 에서 나오지 "안 보는 것" 에서 나오지 않는다.

## 만들지 않기로 한 것

`action.php` 가 제공하지만 쓰지 않는 것들. 출결이라는 본래 목적에 필요하지
않고, 각각 추가 요청을 발생시킨다.

- `smartHistory` / `smartResult` — 차시별 응답 이력 조회
- `hyflexHistory` — 대면/비대면 선택 이력
- `details` — 온라인 강의 진도율 상세
- 백그라운드 알림 — 아이콘 클릭 원칙과 충돌하고, 강의실 밖 사용을 조장한다
- `storage.sync` — 출석 기록이 벤더 동기화 서버로 올라간다

## 아직 확인하지 못한 것

- **출석현황 칩의 실제 텍스트.** 학기 초라 전 과목 전 행이 `-` 다.
  출석/결석/지각이 어떤 문자열로 나오는지 모른다. 그래서 서버 상태는
  캐시에 기록만 하고 건너뛰기 판정에는 쓰지 않는다 — 모르는 문자열을
  "출석함" 으로 오인하면 출결을 통째로 건너뛰게 된다.
  값을 확인한 뒤에 판정에 쓸지 정한다.
- **연강(같은 날 2차시) 실물.** 이번 학기 7과목은 모두 하루 1교시라
  같은 날짜에 두 행이 생기는 경우를 실제로 보지 못했다. 코드와 테스트는
  그 경우를 상정해 두었다.
- **모달 구조.** 첫 실제 세션에서 캡처 모드로 확인한다.

## 업로드 시점

version 은 2.0.0 이지만 Phase 3(제출) 이 끝나기 전에는 동작하지 않는 골격이다.
실제 출결 세션으로 검증하기 전까지 스토어에 올리지 않는다.

## 서버 응답을 저장소에 넣지 않는다

PLATO 페이지를 그대로 저장한 파일에는 **`MOODLE_WSTOKEN`(웹서비스 토큰),
`sesskey`, 이메일** 이 들어 있다. 공개 저장소에 올리면 자격증명을 유출하는
것이고, 일부만 발췌해도 안전을 보장하기 어렵다. 벤더 마크업을 재배포하는
문제도 있다.

대신 우리가 다시 쓴 합성 픽스처를 둔다 (`tests/fixtures/`). 값은 전부 지어낸
것이고, 우리가 실제로 의존하는 구조만 담는다.

    smart-answer-open.html   자동출결이 열려 있는 상태
    smart-answer-done.html   출석 처리된 뒤

픽스처가 현실과 어긋나지 않는지는 두 겹으로 본다:

1. `tests/real-session.test.mjs` — 실제 저장본이 **로컬에** 있으면 대조한다.
   폼 id, 마감 시각 패턴, `$.post` 파라미터 이름 집합, 칩 클래스가 같은지.
   없으면 합성 픽스처만 검증하고 넘어간다.
2. debug 페이지의 자가진단 — 라이브 서버와의 차이는 이쪽이 잡는다.
   픽스처는 스냅샷이라 최신화되지 않는 것이 정상이고, 그것이 회귀 테스트의
   목적이다. 서버 변화를 감지하는 것은 픽스처가 아니라 자가진단의 일이다.

## 위음성을 만들지 않는다

출결 확장에서 가장 비싼 실패는 **서버는 출결이 열려 있는데 우리가 없다고
말하는 것**이다. 위양성(없는 걸 있다고 보는 것)은 요청 하나를 더 하고 끝나지만,
위음성은 출결을 놓친다. 비용이 비교가 되지 않는다.

그래서 "없다/아니다" 라고 단정하는 자리마다 근거를 요구한다.

| 판단 | 근거로 인정하는 것 | 인정하지 않는 것 |
|---|---|---|
| 이 강좌는 조회하지 않는다 | 서버가 **출석부 표를 아예 안 보여줌** | shortname 이 해시처럼 생김, 행 수가 0 |
| 이 강좌는 세션이 없다 | 인증번호 폼이 없음 | 조회 실패, 타임아웃 |
| 이 차시는 반영됐다 | 아는 칩 클래스 | 글자, 모르는 칩 |
| 못 본 강좌가 없다 | 모든 단계를 돌았음 | 찾아서 멈췄음 |

특히 **조회 실패를 "세션 없음" 과 같이 취급하지 않는다.** 실패한 강좌는 따로
모아 화면에 알린다 — 출결이 열려 있었는데 못 본 것일 수 있다.

`tests/false-negative.test.mjs` 가 이 경로들을 전부 고정한다. 새로 무언가를
제외하는 코드를 넣을 때는 여기에 케이스를 먼저 추가한다.

## PLATO 변화를 감지하는 세 겹

PLATO 는 예고 없이 바뀐다. 개편 때는 플러그인이 통째로 갈렸고(2026-09),
그 뒤에도 조용히 화면이 늘었다(2026-09-04, 출결 요약 섹션). 종류가 달라서
한 가지 장치로는 못 잡는다.

| 겹 | 무엇을 잡나 | 언제 | 비용 |
|---|---|---|---|
| 셀렉터·패턴 검사 | **우리가 쓰는 것이 깨졌나** | 자가진단 (수동) | 페이지 2~3개 |
| 액션 등록 확인 | API 이름이 사라졌나 | 자가진단 (수동) | POST 2회 |
| 상태 범례 대조 | 서버가 **상태를 늘렸나** | 자가진단 (수동) | 0 (같은 페이지) |
| 마크업 감시 | 서버가 **화면에 무언가 더했나** | 매 스캔 | 0 (이미 받은 문서) |

앞의 셋은 "우리가 아는 것" 을 확인한다. 그래서 서버가 **더하는** 변화는 놓친다 —
2026-09-04 가 정확히 그랬다. 기존 기능이 멀쩡해 아무 경보도 울리지 않았고,
사람이 결석 예시를 들여다보다 우연히 발견했다. 그때 우리가 모르던 상태(조퇴)가
드러났다.

마크업 감시는 그 빈틈을 메운다. 본문의 클래스 토큰을 기준선(`KNOWN_MARKUP`)과
대조해 **처음 보는 토큰**만 알린다.

- 실측상 이 집합은 매우 안정적이다. 같은 페이지를 다시 받아도, 다른 강좌를
  받아도 차이가 **0** 이었다. 반면 09-02 저장본과 비교하면 신규 25개가 그대로
  드러났다. 노이즈 없이 실제 변경만 잡힌다.
- 사라진 토큰은 알리지 않는다. 인증번호 폼처럼 상황에 따라 없는 것이 정상이다.
- 세션이 열렸을 때만 나타나는 토큰도 기준선에 넣어 두었다. 그러지 않으면
  출결이 처음 열릴 때 헛경보가 난다.
- 사용자가 "확인했음" 을 누르면 그 토큰들은 다시 알리지 않는다.

### 사용자에게는 알리지 않는다

마크업 변화는 **개발자 신호**다. 팝업에 띄우지 않는다 — 사용자가 할 수 있는
일이 없고, 화면이 조금 바뀌어도 출결은 잘 되고 있을 수 있다. debug 페이지에서만
본다.

사용자에게 알리는 것은 딱 하나, **아무것도 알아보지 못한 경우**다. 조회한
강좌에서 출석부 표도 인증번호 폼도 찾지 못하면 "출결이 없다" 가 아니라
"우리가 못 본다" 이고, 그 둘은 사용자에게 전혀 다른 상황이다.

    PLATO 화면이 바뀌어 출결을 확인할 수 없습니다
    FFlato 업데이트를 기다려주세요. 그때까지는 PLATO에서 직접 진행해주세요.

## 공개 저장소에서 유지할 것

- 내부에서만 쓰는 함수는 `export` 하지 않는다. 밖으로 열린 이름은 그 자체로
  "여기서 쓰라" 는 신호가 되고, 읽는 사람이 호출부를 찾아 헤매게 된다.
  테스트만 쓰는 export 는 순수 함수에 한해 허용한다
  (`prune`, `sanitize`, `selectCourses`, `withinWindow`, `interpretResult`).
- 오류는 메시지 문자열이 아니라 `err.kind` 로 구분한다. 화면이 메시지를
  뒤져 분기하면 문구만 바뀌어도 깨진다.
- **사람이 읽는 문자열로 분기하지 않는다.** PLATO 는 한국어·영어·중국어를
  지원하므로 서버 메시지도 화면의 배지도 언어에 따라 바뀐다. 언어와 무관한
  것(응답에 박히는 `[액션이름]`, `shortname` 의 학수번호)으로 판별한다.
  `tests/i18n.test.mjs` 가 이 규칙을 코드 전체에 대해 검사한다.
- **PLATO 마크업에 대한 의존은 `src/config/selectors.js` 한 곳에 모은다.**
  CSS 셀렉터뿐 아니라 HTML 원문에 거는 정규식(`PATTERNS`)도 여기 둔다.
  그래야 자가진단이 전부 훑을 수 있다.
- 버전의 출처는 `manifest.json` 하나다. `package.json` 에 version 을 두지 않는다.
- 일회성 스크립트는 남기지 않는다. `tools/` 에는 반복해서 쓰는 것만 둔다.
